# Сводка отклонений по дивизиону

Экран руководителя верхнего уровня замыкает управленческий цикл сверху: он
показывает, где именно в области ответственности находятся отклонения, по каким
из них задача ещё не поставлена и какие задачи вышли за срок.

## Что реализовано

### Сервер
- `GET /api/v1/metrics/divisions/deviations?start&end[&division]` —
  `server/src/metrics/divisionSummary.ts`. Новых таблиц и миграций не потребовалось:
  сводка считается по опубликованным срезам, настроенным порогам, задачам по
  отклонениям и действующим назначениям.
- Разрезы: по дивизионам, внутри дивизиона по региональным менеджерам, при
  раскрытии — по филиалам с перечнем красных и жёлтых показателей.
- Разбор по показателям: сколько филиалов дивизиона красные и жёлтые по каждому
  показателю, чтобы отличить проблему одного филиала от системной.
- Сроки задач считаются от настройки `deviation_task_due_soon_hours`, а не от
  зашитого значения; действующее окно возвращается в ответе.

### Принципиальные ограничения, заложенные в расчёт
- Сводка не обходит разграничение доступа: в неё попадают только филиалы и
  показатели, на которые у пользователя есть допуск READ. Отзыв допуска убирает
  филиал, а вместе с последним филиалом — и дивизион.
- Отсутствие опубликованного значения показывается отдельным признаком
  (`metrics_missing`, `branches_without_data`) и никогда не приравнивается к нулю
  или к выполнению плана.
- Филиал относится к дивизиону по подчинённости, действующей на дату конца
  периода, поэтому смена структуры не переписывает историческую сводку.
- Региональный менеджер определяется действующим назначением на филиал; вакансия
  показывается явно и не переносится на дивизион. При нескольких действующих
  назначениях берётся самое раннее по дате вступления в силу.
- Показатель без настроенного порога попадает в отдельный перечень: статус по
  нему не рассчитывается и не считается зелёным.

### Клиент
- Страница `/division-summary` «Сводка по дивизионам» в разделе меню
  «Управление результатом»: период, фильтр по дивизиону, итоги, разбор по
  показателям, таблица региональных менеджеров и раскрываемый перечень филиалов
  со ссылками на карточку филиала.
- Чистая модель `client/src/components/divisionSummaryModel.ts`: порядок фокуса,
  подпись вакансии, подпись отсутствующих данных.

## Расхождения и ограничения
- Дивизиональные планы и целевые доли рынка в сводке не используются: таких
  подтверждённых данных в портале нет, а выдумывать план нельзя.
- Постановка задачи прямо из сводки пока не сделана: переход выполняется через
  карточку филиала. Это следующий естественный шаг.
- Сравнение с предыдущим периодом не выводится: для него нужен согласованный
  перечень сопоставимых периодов по каждому показателю.
- Уровень кластера в разрезах не показывается отдельно, филиалы кластера
  попадают в свой дивизион.
