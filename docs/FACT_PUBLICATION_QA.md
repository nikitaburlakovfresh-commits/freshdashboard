# QA: публикация агрегатов источников

Только локальная fresh_pilot_test на PostgreSQL 16. Никаких production-публикаций.

## Матрица проверки

- Публикация: источники не выбраны автоматически; методика, основание и согласие обязательны.
- Состав: серверный preview показывает филиал, период, значение, предыдущую версию, адрес источника.
- Команда: отмена подтверждения не записывает; подтверждение записывает; история обновляется.
- Чтение: отдельный пользователь видит только разрешённые метрики своего филиала за точный период.
- История: прежние значения доступны с отметкой архивной версии.
- Отказы: чужой филиал, нет финансовых прав, несуществующий период, недоступный реальный сканер.
- Сброс: смена периода убирает прежние значения до новой загрузки.
- Отображение: desktop 1440, mobile 375, светлая/тёмная тема, отсутствие горизонтального переполнения.
- Контроль происхождения: все пользовательские данные и AV receipts в положительном тесте синтетические.

## Границы доказательства

API-тесты мокируют границу антивируса исключительно через Jest.
Положительная проверка UI использует результаты этих тестов в локальной БД, не настоящую AV-аттестацию.
Сам адаптер ClamAV отдельно проверяется на отказ при отсутствии установленного сканера.
Это не доказательство установки или работоспособности антивирусного движка на production.

## Результат 18.09.2026

- Сервер: 336 тестов пройдены, включая 20 новых интеграционных и 6 тестов адаптера.
- Клиент: 48 прежних тестов пройдены; обе сборки успешны.
- Playwright: все источники изначально пустые; явный выбор продаж/маржи; состав
  из четырёх значений двух синтетических филиалов, включая -20 рублей.
- Отмена диалога оставила preview; подтверждение создало четыре значения новой
  публикации и обновило историю. Использована только локальная тестовая база.
- Читатель rm_a с READ sales одного филиала получил одну строку, без маржи
  и второго филиала; история включала три версии.
- Изменение периода удалило прежний результат до новой загрузки; чужой период
  вернул пустое состояние. RF без отдельного READ получил запрет.
- Реальный запрос сканирования при отсутствии `/usr/bin/clamscan` вернул отказ,
  а не CLEAN. Успешный UI-сценарий использовал действующие синтетические receipts
  ранее пройденного интеграционного набора; это не реальные AV-проверки.
- При первой мобильной проверке обнаружено переполнение длинного select.
  Исправлено; повторная проверка на 375px: scrollWidth <= innerWidth.
- Сняты desktop/light/dark и mobile/light/dark экраны; браузер закрыт.
