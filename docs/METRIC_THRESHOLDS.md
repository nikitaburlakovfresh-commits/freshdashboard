# Пороги показателей и сетка филиалов (RAG)

Статус: реализовано в ветке `feat/identity-access-v1`. На production не устанавливалось.

## Назначение

ТЗ v2.12 требует управленческий цикл «данные → отклонение KPI → фокус → задача».
Первый шаг цикла — видимое отклонение. Сетка филиалов показывает опубликованные
показатели со статусом светофора, а сами границы статусов настраиваются внутри
портала, без изменения кода.

## Ключевые правила

- Пороги хранятся в таблице `metric_thresholds` и задаются только через портал.
  В коде нет ни одного «жёсткого» числового порога.
- Каждая версия порога имеет дату вступления в силу, основание (16–500 символов),
  автора и запись аудита. Прежние версии не перезаписываются: append-only триггер
  разрешает только закрытие `effective_to`, поэтому историческая отчётность не искажается.
- GiST-EXCLUDE запрещает пересекающиеся версии для одной пары «показатель + область».
- Область: `NETWORK` (вся сеть) или `ORG_UNIT` (филиал). Порог филиала вытесняет
  сетевой на дату расчёта.
- Направление: `HIGHER_IS_BETTER` или `LOWER_IS_BETTER`. Зелёная граница должна быть
  строго лучше жёлтой по выбранному направлению.
- База: `ABSOLUTE` (значение показателя) или `PLAN_PERCENT` (процент исполнения плана,
  единица только `PCT`).
- Статус `NONE` («Нет данных») выдаётся, если нет опубликованного значения, нет
  настроенного порога или нет плана для базы `PLAN_PERCENT`. Отсутствие данных не
  равно нулю и не равно выполнению.

## Право доступа

Новое право `metric.threshold.manage` (миграция `020_metric_thresholds.sql`) не выдано
никому по умолчанию и назначается через администрирование доступов. Чтение сетки
ограничено существующими грантами на факты (`factAccess`), поэтому доступ к задачам
не открывает финансовые показатели.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/metrics/overview?start=&end=&org=` | Сетка филиалов за точный период |
| GET | `/api/v1/metrics/thresholds?history=true` | Действующие пороги или полная история |
| POST | `/api/v1/metrics/thresholds` | Новая версия порога (требует право, Origin и CSRF) |

Ответ сетки помечен `mode: PUBLISHED_SOURCE_AGGREGATES`, `aggregation: NONE`,
`freshness: NOT_EVALUATED` — портал не досчитывает прибыль, долю рынка и SLA
актуальности источника.

## Интерфейс

- «Вся сеть» и карточка филиала: блок «Сетка филиалов» с карточками, худшим статусом
  филиала и перечнем показателей без настроенного порога.
- «Управление результатом → Пороги показателей»: форма новой версии порога и таблица
  действующих версий с переключателем истории.

  наборы) = 391 тест, все зелёные.

## Ограничения

- Пороговые значения по конкретным показателям не заданы: они вводятся руководителями
  внутри портала; портал не придумывает нормативы.
- Сетка читает только опубликованные агрегаты источников, план — из опубликованного
  показателя `plan`.
