# Экран «Мои задачи по отклонениям»

Рабочий экран ответственного (функционального руководителя): что именно с него
требуется по отклонениям показателей, по какому основанию и к какому сроку.

## Что сделано

Сервер `myDeviationTasks` в `src/metrics/deviationTasks.ts`, маршрут
`GET /api/v1/metrics/deviation-tasks/mine?state=OPEN|ALL`:

- отбор строго по себе: только задачи, где текущий пользователь является
  ответственным в `work_items`; чужие задачи и задачи без назначения не видны;
- `state=OPEN` (по умолчанию) — DRAFT, ASSIGNED, IN_PROGRESS, SUBMITTED;
  `state=ALL` добавляет закрытые и отменённые;
- по каждой задаче: филиал, показатель, период, статус отклонения на момент
  постановки, основание, текст причины, название и статус задачи, срок,
  признак приостановки и её причина, версия сущности;
- сортировка по сроку: ближайший срок выше;
- `due_state` считается по факту: `OVERDUE` (срок истёк), `DUE_SOON` (менее 72
  часов), `ON_TRACK`, `CLOSED`; счётчики `total`, `overdue`, `due_soon`,
  `blocked` возвращаются вместе с перечнем.

### Разграничение доступа

Экран **не требует** отдельного допуска к бизнес-показателям: человек видит
основания собственных задач. Числовые значения показателя и порога отдаются
только при наличии `report_fact_access` READ на этот филиал и показатель. Иначе
возвращается `values_visible=false`, а значения — `null`, и интерфейс пишет
«Значения скрыты: нет допуска к показателю». Отсутствие допуска не подменяется
нулём и не выдаётся за отсутствие отклонения.

Клиент: страница `/my-deviations` (`pages/MyDeviationTasksPage.tsx`), пункт меню
«Мои задачи по отклонениям» в разделе «Операционная работа», переключатель
«В работе / Все», счётчики, переходы в карточку задачи и карточку филиала.
Чистая логика подписей — `components/myDeviationTasksModel.ts`.

## Исправлено попутно

Карточка филиала была объявлена на `/branches/:id`, который уже занят сеткой
(`/branches/:orgId` → OperationalPage), поэтому маршрут был недостижим. Карточка
перенесена на `/branch-card/:id`; ссылки в сетке филиалов и заголовок раздела
обновлены.

## Ограничения

- Экран не меняет статус задачи: работа с задачей остаётся в её карточке.
- Порог «срок близко» задан константой 72 часа в коде и пока не выведен в
  настройки портала — это расхождение с требованием полной настраиваемости.
- Ответственный не подставляется автоматически при постановке задачи.
