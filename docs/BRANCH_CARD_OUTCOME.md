# Карточка филиала: история отклонений и проверка результата

Замыкает управленческий цикл ТЗ v2.12: задача ответственному → действие →
проверка результата → влияние на показатель.

## Что сделано

Сервер `src/metrics/branchCard.ts`, маршрут `GET /api/v1/metrics/branches/:id?start&end`:

- показатели филиала за период — только опубликованные значения в пределах
  допусков пользователя к метрикам, со статусом по настроенным порогам,
  направлением порога, основанием статуса и номером ревизии;
- история отклонений филиала: все задачи, поставленные по отклонениям (до 200,
  новые сверху), с периодом, зафиксированным значением и статусом на момент
  постановки, основанием, названием, статусом и сроком задачи;
- проверка результата `verifyOutcome`: сравнивается зафиксированное значение с
  текущим опубликованным значением того же периода. Статус текущего значения
  считается по порогам, действующим на конец периода отклонения, а не по
  порогам выбранного фильтра.

Исходы (честные формулировки, без подмены отсутствия данных нулём):

| Исход | Значение |
|---|---|
| `NO_PUBLISHED_VALUE` | за период нет опубликованного значения |
| `NOT_REPUBLISHED` | показатель не переопубликован — результат не подтверждён |
| `STATUS_IMPROVED` / `STATUS_WORSENED` | статус изменился после новой публикации |
| `STATUS_UNKNOWN` | новое значение есть, но статус не определён (нет порога или плана) |
| `UNCHANGED` | значение не изменилось |
| `VALUE_IMPROVED` / `VALUE_WORSENED` | значение изменилось с учётом направления порога, статус тот же |

Ключевое правило: закрытие задачи само по себе не считается влиянием на
показатель, а отсутствие новой публикации не выдаётся за улучшение.

Клиент: страница `/branches/:id` (`pages/BranchCardPage.tsx`) с показателями
периода и таблицей «было → стало → изменение → результат → задача»; переход в
карточку из названия филиала в сетке; чистая логика подписей и знака изменения в
`components/deviationOutcomeModel.ts`.

## Ограничения

- Направление «лучше/хуже» берётся из версии порога, зафиксированной в
  основании задачи; при смене методики порога прошлые исходы не переписываются.
- История не ограничена выбранным периодом фильтра — период задаёт только блок
  показателей вверху карточки.
- Отдельного показателя «доля закрытых задач» не вводилось: он требует
  согласованной методики и планов.

## Тесты

- `server/test/branchCard.metrics.ts` — 10 тестов: сессия и допуск к метрикам,
  изоляция чужого филиала, четыре некорректных фильтра, состав показателей и
  метрики без порога, отсутствие подтверждения без новой публикации,
  подтверждённое улучшение, обратное направление показателя и ухудшение,
  таблица исходов `verifyOutcome`.
- Регрессия: серверный прогон 139, изолированные наборы 286, клиент 59,
  типизация и сборки клиента и сервера без ошибок.
