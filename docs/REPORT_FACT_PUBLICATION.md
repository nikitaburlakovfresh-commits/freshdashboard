# Публикация агрегатов отчётов: граница beta

## Что реализовано

Добавочная миграция 017 создаёт отдельный реестр утверждённых агрегатов источника.
Черновики `report_review_revisions`, исходные файлы и parser preview не изменяются.
Это промежуточный слой подтверждённых фактов FORM_UI/QLIK, а не полная модель
`metric_snapshot` и Metric Engine из §8 ТЗ v2.12.

Публикация: существующий личный bootstrap-admin с staging-доступом и отдельным
grant-bound PUBLISH-допуском → выбор источника каждой метрики → методика/состав
источника → явное подтверждение периода и UUID-привязок → preview на 10 минут →
повторная проверка и атомарная запись. Без явного выбора метрика не публикуется.

В одной транзакции записываются публикация, значения, история замены, указатель
актуальной версии, audit, outbox (NONE) и результат идемпотентной команды.
Отзыв прав проверяется до возврата ранее сохранённого ответа.

## Барьеры

- Историческая цепочка принадлежности филиала должна покрывать весь период.
  Демо-единицы, несопоставленные строки, чужая сеть и история с разрывом запрещены.
- Итог выбранной метрики сверяется со всеми строками её источника.
  Пропуск числа не превращается в ноль; отрицательные денежные значения сохраняются.
- Для каждой метрики выбирается один источник. В этот реестр сохраняется явный
  выбор конкретной публикации, а не выдуманное глобальное правило приоритета.
- Период продаж берётся из подтверждаемого черновика, плана из его отдельных дат,
  склада из проверенного заголовка. Периоды не складываются.
- Выручка из summary пока запрещена: существующий parser не проверяет её заголовок.
  Прочие колонки доступны только в поддержанных форматах.
- Хеш и целостность закрытого оригинала повторно проверяются перед публикацией.
- Все оригиналы пакета должны иметь свежий CLEAN receipt (не старше 24 часов).
- Смена черновика, результатов сканирования, предыдущей версии или истечение
  preview требует новой проверки. Повтор того же успешного запроса безопасен.

## Антивирус: обязательная подготовка окружения

Адаптер запускает только `/usr/bin/clamscan`, без shell и пользовательских аргументов.
Источник передаётся через stdin, не отправляется внешнему сервису.
Сигнатуры должны иметь проверяемую дату не старше 48 часов; версия до и после
сканирования должна совпадать. Зашифрованные архивы и превышение лимитов
сканирования включают тревогу. Timeout 30 секунд, ограниченный вывод.

Миграция не устанавливает ClamAV. Runtime и отдельный updater подготовлены
в следующем кандидате; реальные CLEAN/EICAR и API-публикация проверены локально.
Подробные доказательства и оставшиеся серверные барьеры: `BETA_RELEASE_GATE.md`.
Не включать реальные публикации до проверки ресурсов, restore и установки.

Ошибка нового сканирования не создаёт CLEAN и не продлевает прежний receipt.
Уже действующий CLEAN остаётся действующим до своего срока. Скачивание
оригиналов через старый endpoint по-прежнему запрещено.
Старый staging API сохраняет свою прежнюю семантику preview; текущие результаты
сканирования и публикации читаются через отдельный `/report-facts/:id/publication`.

## Доступ и операционный долг

Таблица `report_fact_access` не получает записей автоматически.
READ ограничен существующим ORG_UNIT grant и перечнем метрик; PUBLISH не даёт READ.
SUPER_ADMIN и право читать задачи сами по себе не дают чтение финансовых значений.

Для первичной beta подготовлена операторская команда:

```text
node server/dist/scripts/provisionFactAccess.js <grant-uuid> READ|PUBLISH <metric,metric> <approval-reference>
```

Она не создаёт назначения, не расширяет права роли, не перезаписывает и не
восстанавливает прежний допуск. Выполнять только после отдельного согласования
конкретного grant и перечня метрик. В этой сессии production-команда не выполнялась.

Выдача/отзыв, сроки, предварительная проверка и история доступны в следующем
модуле `/access/metrics`: см. `METRIC_ACCESS_ADMIN.md`. Операторская команда
остаётся только для отдельно согласованного первичного включения.

## Чтение

`GET /api/v1/report-facts?start=YYYY-MM-DD&end=YYYY-MM-DD[&org=UUID][&history=true]`
читает только утверждённые значения за точно совпавший период с проверкой
действующих индивидуальных допусков. Прежние версии помечаются архивными.
Суммирования между филиалами и периодами нет; текущие названия филиалов не
переписывают UUID/период/источник исторического значения.

Привязка к source file hash, адресу ячейки, версии parser/review, scan receipt,
методике и основанию выбора источника хранится в каждом snapshot.
Значения не заполняют ежедневники автоматически.

## Не заявляется завершённым

Полный каталог метрик, расчёт SQL/DSL, формулы прибыли и рыночной доли,
планы/пороги, перевычисление, SLA свежести, расписание импорта, Report Builder,
rollback отдельной кнопкой, все 13 QLIK-форматов,
публикация реальных данных, установка на production и бизнес-приёмка.
Исправление сейчас возможно новой явной публикацией с сохранением старых версий.

## Проверки

`metricPublication.beta.ts`: 20 интеграционных сценариев с настоящей локальной PG16.
`scanner.test.ts`: 6 проверок адаптера на подменённой границе процесса.
В положительных API/UI-тестах AV receipt синтетический. Это не антивирусная
сертификация реальных файлов и не доказательство готовности production ClamAV.
Общие регрессионные наборы запускаются раздельно: каждый сбрасывает только
защищённую локальную БД fresh_pilot_test.
