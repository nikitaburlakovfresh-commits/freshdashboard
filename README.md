# FRESH Portal: пилот задач R1

Тестовый портал для двух синтетических филиалов. Не предназначен для реальных персональных или финансовых данных до отдельной приёмки и проверки защиты.

## Возможности

Вход по паролю, доступ по филиалу и роли, создание и назначение задач, исполнение, сдача результата, возврат на доработку, приёмка, история и уведомления внутри портала.

БДР, Telegram, вложения и offline-режим не входят в этот выпуск.

## Каркас портала R1.1

Главная страница теперь является дашбордом. Общее меню объединяет дашборд, продажи и склад, БДР, KPI/MBO, задачи, ежедневник и уведомления.
Счётчики и ближайшие действия рассчитываются по доступным задачам; при неполной загрузке явно отмечается ограничение.
Карточки бизнес-показателей не содержат вымышленных чисел: источники ещё не подключены.
БДР, KPI/MBO, аналитика и ежедневник представлены навигационным каркасом, не готовыми расчётными модулями. Конфигуратор виджетов и остальные роли полного ТЗ пока не реализованы.
Изменения R1.1 подготовлены в коде и предпросмотре; развёртывание этого обновления на основном сервере требует отдельного шага.

## Технологии и проверка

Node.js 22, Express, PostgreSQL 16, React, Docker Compose, Caddy.
62 автоматических интеграционных теста прошли на локальной PostgreSQL 16. Это не полное покрытие 80 сценариев контракта и не доказательство готовности к промышленной эксплуатации.

## Развёртывание

1. Создать приватный `.env` с `PGPASSWORD`, `SESSION_HMAC_SECRET`, `CSRF_HMAC_SECRET`, `ALLOWED_ORIGIN=https://freshdaily.ru`. Секреты генерировать случайно; права файла 600.
2. `docker compose build app`
3. `docker compose up -d db`
4. `docker compose run --rm app node server/dist/scripts/migrate.js`
5. Для тестовых учётных записей запустить с отдельным приватным env-файлом: `docker compose run --rm --env-from-file pilot-users.env app node server/dist/scripts/seed.js`. Он должен содержать `ALLOW_SYNTHETIC_PILOT_SEED=true` и четыре разных `PILOT_PASSWORD_RM_A`, `PILOT_PASSWORD_RF_A`, `PILOT_PASSWORD_RM_B`, `PILOT_PASSWORD_RF_B` длиной не менее 20 символов. Эти файлы никогда не публиковать.
6. `docker compose up -d`

Порт 4000 доступен только с сервера; порт PostgreSQL наружу не опубликован. HTTPS требует корректного DNS и доступных портов 80/443.

## Ограничения пилота

- Ограничение частоты запросов хранится в памяти одного процесса; балансировка на несколько процессов не поддерживается.
- Конкурентный отзыв прав/сессий требует дополнительной проверки и усиления транзакционных блокировок до промышленного запуска.
- Повтор команды после перезагрузки страницы или истечения срока идемпотентности требует проверки её фактического результата.
- Внешнее резервное копирование и восстановление ещё не приняты.
- Миграция создаёт исходную схему; это не полноценная система версионирования миграций.
- Тестовые пользователи не являются административным интерфейсом управления сотрудниками.
